## API Discrepancies Discovered

| Module | Issue | Impact |
|--------|-------|--------|
| **Inventory.luau** | `UseItem()` references `Enum.ItemType.Consumable` (Roblox enum) instead of the custom `ItemType` enum from Data/Items. The Items module defines its own ItemType table, not a Roblox Enum. | `UseItem` will crash at runtime if the Items module's type values don't match Roblox Enum values. |
| **Inventory.luau** | All methods reference global `Items.Get()` without importing it. This is a Roblox module-require convention (global injection). | Works in Roblox if `Items` is injected into `_G`; fails in isolation. |
| **Harvesting.luau** | `GetToolStats()` references global `Items.Get()` and `Enum.ItemType.Tool` | Same as Inventory — depends on global Items and Roblox Enum |
| **Harvesting.luau** | `UpdateToolDurability()` references undefined `playerCharacter` variable (line 205) | Runtime error: `playerCharacter` is never defined in scope |
| **Trading.luau** | `StartTrade()`, `ListItem()`, `BuyItem()` depend on `game.Players`, `game:GetService("MarketplaceService")` | Fully Roblox-dependent, cannot be unit-tested outside Studio |
| **Events.luau** | Uses `Enum.create()` and `Vector3.new()` at module scope | Lune-compatible only if mocked; the Data module specs mock these |
| **Creatures.luau** | `Tame()` references `player:GetAttribute("Inventory")` for inventory access | Unusual pattern — stores Inventory in an Attribute, not a module reference |
